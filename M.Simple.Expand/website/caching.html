M.Simple.Caching

M.Simple.Caching 接入与使用

提供 ISimpleCache、内存后端、JSON 快照、过期策略及进程内异步加载合并。每个容器只注册一个后端；Redis 或 MongoDB 项目使用相应适配包替换内存注册。

当前项目版本 1.0.0.5，目标框架 .NET 8。

安装包

在使用方项目目录执行，或通过 --project 指定项目：

powershell
dotnet add package M.Simple.Caching --version 1.0.0.5

包源需包含该版本。安装包不会自动执行注册；保留项目原有配置，无需添加示例接口。

Program.cs 配置

csharp
using M.Simple.Caching; // 本次新增：引入本包接入所需扩展或类型。

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();
// 本次新增：注册独立内存缓存及统一缓存接口。
builder.Services.AddSimpleMemoryCache(options =>
{
    options.KeyPrefix = "MyApi:Development:";
    options.DefaultExpiration = TimeSpan.FromMinutes(10);
});

var app = builder.Build();

app.UseAuthorization();
app.MapControllers();
app.Run();

使用说明

缓存与数据库事务独立。后端或序列化错误会传播，不会静默降级；业务应能够重新加载缓存数据。

使用

csharp
public sealed class ProductService(ISimpleCache cache)
{
    public Task<ProductDto?> GetAsync(long id, CancellationToken cancellationToken)
        => cache.GetOrCreateAsync<ProductDto?>(
            $"product:{id}",
            ct => LoadFromDatabaseAsync(id, ct),
            new SimpleCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(5)
            },
            cancellationToken);
}

上面的 LoadFromDatabaseAsync 由业务实现。其他操作：

csharp
await cache.SetAsync("product:1", product);
var result = await cache.TryGetAsync<ProductDto>("product:1");
if (result.Found)
{
    var value = result.Value; // Found 与 null、0、false 的值分开判断。
}
bool exists = await cache.ExistsAsync("product:1");
await cache.RemoveAsync("product:1");

数据库更新成功后再删除相应缓存。缓存不参与数据库事务。

过期与空值

  • 未设置单条策略时使用 DefaultExpiration，默认 10 分钟。
  • 只设置 SlidingExpiration 表示纯滑动过期；同时设置绝对和滑动期限时，读取刷新滑动期限，但不超过绝对上限。
  • NeverExpires=true 表示不主动过期，不能同时配置绝对/滑动期限；仍可能因内存容量被淘汰。
  • ExistsAsync 不刷新滑动期限；TryGetAsync 和 GetOrCreateAsync 命中会刷新。
  • 支持的相对期限为 1 毫秒至 3650 天；远端后端按毫秒向上取整。
  • GetOrCreateAsync 默认不缓存 null。可全局设置 CacheNullValues=true，或在单条策略覆盖。
  • SetAsync 显式存储 null 时视为有效缓存项。所有 null 项均受 NullExpiration（默认 30 秒）的绝对上限约束，NeverExpires 也不会使 null 永久缓存。
csharp
var item = await cache.GetOrCreateAsync<ProductDto?>(
    "product:missing",
    ct => FindProductAsync(ct),
    new() { CacheNullValues = true });

await cache.SetAsync("hot", product, new()
{
    SlidingExpiration = TimeSpan.FromMinutes(2),
    AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(30)
});

并发、取消与更新

  • 同一个 ISimpleCache 单例、同一个 Key 的并发未命中共享一次加载。不同泛型类型不能共享 Key；第一个加载者的工厂与策略用于此次共享加载。
  • 工厂抛出的异常不会缓存，下一次可以重试。
  • 调用方 CancellationToken 只取消自己的等待，不取消其他调用方共享的工厂。
  • 工厂使用独立的 FactoryTimeout（默认 30 秒，最多 1 天）及容器关闭令牌；超时抛出 OperationCanceledException。忽略令牌的业务代码仍可能在后台执行，但晚到结果不会写入缓存。
  • 本进程内显式 Set/Remove 会阻止此前工厂完成后覆盖/重新写入缓存。已经等待旧工厂的调用者仍可能收到旧返回值。
  • Redis/MongoDB 共享存储，但不提供分布式加载锁；不同实例可能分别加载。跨实例的数据库更新与缓存失效也不具有原子性，需业务按一致性要求协调。

序列化、容量与生命周期

所有实现统一使用 System.Text.Json，存入/取出均为快照，不共享调用方的可变对象引用。缓存时与读取时应使用相同泛型类型；类型标记不包含 DTO 所在程序集的版本号，但升级时仍需保持 DTO JSON 结构兼容，必要时更新 KeyPrefix。SerializerOptions 可在注册时设置。

MaxPayloadBytes 默认 1 MiB，限制单次写入的 JSON 大小。内存缓存使用独立 MemoryCache，不修改宿主已有 IMemoryCache 的设置；同时限制条目数与估算字节权重（JSON、Key、类型名及固定开销），实际 GC 内存不是硬配额。容量紧张时可能淘汰或拒绝缓存项；业务应始终能够重新加载。

KeyPrefix 默认空字符串，推荐包含应用和环境。原始 Key 不能空白，前缀和 Key 总长不能超过 1024 字符。注册后不要修改配置对象。ISimpleCache 和后端均为单例，由 DI 容器释放；工厂不要捕获生命周期短于缓存服务的资源，需使用时自行创建作用域。

后端连接/序列化错误会传播给调用方，不会静默降级成内存或未命中。取消网络等待不能保证服务端操作回滚。

独立原生读取

新增 ISimpleNativeCache，专门读取后端原生数据，不改变 ISimpleCache.TryGetAsync<T>、写入格式、加载合并或 Dashboard 的管理范围。核心包 1.0.0.5、Redis 包 1.0.0.6、MongoDB 包 1.0.0.5 起提供本节 API。

安装所选后端包后仍只注册一个后端；后端注册自动提供 ISimpleNativeCache。使用默认行为无需额外调用配置方法。可按需增加以下独立配置，注册顺序不限：

csharp
using M.Simple.Caching;

builder.Services.AddSimpleNativeCache(options =>
{
    options.Scope = NativeCacheScope.Prefixes;
    options.Prefixes = ["ids:", "urn:"]; // 多前缀取并集，区分大小写，按字面比较
    options.MaxPayloadBytes = 1024 * 1024;
    options.MaxCollectionItems = 1000;
});

// 注入 ISimpleNativeCache nativeCache 后：
var result = await nativeCache.TryGetAsync<Product>("ids:product:1", cancellationToken);
if (result.Found) Console.WriteLine(result.Value);
var exists = await nativeCache.ExistsAsync("urn:product:1", cancellationToken);
NativeCacheScope业务原生读取范围
CurrentApplication（默认）完整 Key 必须以当前业务 KeyPrefix 开头；业务前缀必须非空
Prefixes完整 Key 必须匹配配置的任一前缀，至少配置一个非空前缀
All当前后端存储范围内的任意完整 Key

所有模式均传完整 Key，不自动拼接、不依次尝试多个前缀。越界、空白或超过 1024 字符的 Key 抛出 ArgumentException。配置数组和 JSON 序列化选项会取快照；运行时修改调用方配置不会扩大访问范围。Scope/Prefixes 的校验独立于 Dashboard；例如管理页面设置 All 时，业务原生读取仍默认 CurrentApplication。NativeCacheScope 不提供 AllManaged，因为读取协议在这里由原生类型决定。

后端TryGetAsync<T> 的数据协议
Redis只读原生 String；byte[] 原样返回，string 严格按 UTF-8 解码，其他 T 使用独立 SerializerOptions 按 JSON 反序列化
MongoDB使用字符串 _id 精确查询整个文档，按 MongoDB BSON 序列化规则映射为 T；支持 BsonDocument，byte[] 返回原始 BSON 文档字节
内存读取本包独立存储实例中的 JSON payload；byte[] 返回 JSON 字节，其他 T 按 JSON 映射，不使用本包类型标记校验

Redis 中本包写入的 Hash 不会自动解包，使用原有 ISimpleCache 读取；MongoDB 中本包文档也不会自动提取 payload。MongoDB 的字符串 Key 不会自动转换成 ObjectId，不接收管理页面生成的 ~mongo: 标识；本版原生业务接口只支持字符串 _id。若 DTO 不映射 _id 等字段，可使用 BsonIgnoreExtraElements，字段映射使用 BsonElement/BsonId 等驱动规则；JSON SerializerOptions 不影响 BSON 映射。

Redis 集合使用明确的方法，返回原始字节值，不把集合强制转换成任意 DTO：

csharp
var hash = await nativeCache.HashGetAllAsync("ids:hash", cancellationToken);
// hash.Value 是 IReadOnlyDictionary<string, byte[]>；字段名要求有效 UTF-8。
var list = await nativeCache.ListRangeAsync("urn:list", start: 0, count: 100,
    cancellationToken: cancellationToken);
var members = await nativeCache.SetMembersAsync("urn:set", cancellationToken);
var scores = await nativeCache.SortedSetRangeAsync("urn:sorted", start: 0, count: 100,
    cancellationToken: cancellationToken);
// scores.Value 的元素包含 byte[] Member 和 double Score，按分数升序/Redis 排序规则读取。

集合方法均返回 CacheResult；Key 不存在为 Found=false，存在的 List/SortedSet 查询超出末尾时为 Found=true、空列表。HashGetAll/SetMembers 返回整个集合，超过 MaxCollectionItems 会报错；ListRange/SortedSetRange 仅返回显式区间，start 要求非负，count 为 1..MaxCollectionItems。内存和 MongoDB 调用 Redis 集合方法抛出 NotSupportedException。ExistsAsync 在 Redis 中适用于任意原生类型，不要求 String。

未找到才返回 Found=false；JSON null 可返回 Found=true、Value=null。类型错误、JSON/BSON 映射错误、非法 UTF-8、超限和网络异常直接传播，不能将其作为未命中。默认单次读取上限 1 MiB、集合项数上限 1000，可分别配置为 1 字节..64 MiB 和 1..10000 项；Hash 字段名和值、SortedSet 成员和分数字节均计入大小。超限时不返回部分数据，与管理页面的截断预览不同。

原生读取不续期、不增加业务缓存命中/未命中统计，没有写入、删除、GetOrCreate 或自动回填接口。Redis 读取使用原子只读脚本，遵循 Redis TTL；MongoDB 不创建索引、不解释业务文档的 expiresAt 字段，只遵循 MongoDB 的实际存储状态，TTL 物理清理前文档仍可读；内存仍按该存储实例的逻辑过期规则读取。MongoDB 整文档超限在服务器投影时省略正文，随后明确报错。

见可运行原生读取示例。
